# 歡迎訊息、統一成效與人工選版：本波更新規格

日期：2026-10-05（Asia/Taipei）
盤點基準：staging `b713164`。
狀態：待使用者檢閱的設計規格；不是已實作功能，也不是正式上線核准。
只修改 staging；由使用者 push，本階段不部署、不發送真人訊息。

## 目的與已確認範圍

營運可以設定加入好友歡迎訊息，沿用全部現有訊息樣式；從同一個入口查看歡迎、群發、自動化、關鍵字回覆的執行紀錄與成效。
小樣本 Campaign 可等人工確認才發保留名單。營運亦可隔日重新計算動態名單，排除前一批 A/B 測試對象後，手動發選定版本。

本波不新增歡迎訊息 A/B 分流、不新增訂位完成歸因、不補造歷史事件、不重做既有訊息編輯器。
本規格預設只涵蓋主 LINE OA；第二 OA 與 Email 不改動。

## 現況與根據

- `src/routes/lineWebhook.js` 已呼叫 `flowEngine.triggerFollow()`；`src/core/flowEngine.js` 已支援 follow 流程、來源條件、訊息庫發送及 `/rf` 點擊追蹤。新的歡迎設定必須沿用這條路。
- `src/core/messageTapTracking.js` 已遍歷 Flex URI 與原生 Imagemap 區域。現有關鍵字 A/B 具有訊息快照、事件去重、驗證身分點擊及成功回覆人數，不能假設全部只能統計次數。
- `/admin/push-logs` 已有來源、失敗原因、權限、分頁及 CSV；擴充既有入口，不另建重複紀錄頁。
- `/admin/campaign-performance` 已有群發成效；保留原報表及書籤，新入口彙整各來源，不混加不同口徑。
- `campaignExperiment.normalizeCampaignExperiment()` 固定 `winnerMode: 'auto'`。既有批次詳情已有手動釋出按鈕及 `release-experiment-winner` API，且與排程共用 row lock。
- 最新 staging 已支援 Campaign 的 template、sequence、flex_json、imagemap；不可退回舊版只允許 template/sequence 的限制。

## 設計選擇

採用「既有發送流程＋共用成效介面＋新增事件補缺」：保留已驗證的分組、sender、URL 跳板與排程，增補來源／快照／執行身分。
不採取另建整套發送服務（會增加重複發送風險）；也不只把不同來源報表直接相加（分母與事件定義不同，容易誤導）。

## 1. 設定 → 加入好友歡迎訊息

- 新增 `/admin/welcome-messages` 管理入口，以 follow automation 為執行基礎，讓營運不需理解流程步驟即可設定。
- 預設停用；選擇訊息庫素材、預覽、儲存快照後才能啟用。訊息樣式依共用 builder 能力取得，不另外維護少數格式白名單。
- 支援文字、圖片、影片、多圖／Flex、自訂 Flex JSON、原生 Imagemap、多段混排；頂層不存在的類型沿用既有 sequence 表達，不杜撰資料格式。仍遵守 builder 與 LINE 的 1～5 則限制。
- 分別設定首次加好友及解除封鎖；未知好友狀態不猜成首次，記錄略過原因。從已驗簽 follow 事件及既有會員狀態取得依據。
- 同一事件只能申領一次執行；重送、並行 webhook、已完成流程再次收到同事件都不能重複發送。逾時列為不確定，不自動用新識別重送。
- 管理頁列出現存啟用中的 follow 發訊流程，提示可能重複；不自動停用流程或 LINE 原生後台歡迎訊息。啟用前須明確確認重複設定檢查。
- 修改素材不回寫已發送快照；選取新的素材內容才建立新設定版本。停用擋住未開始的歡迎發送，已被 LINE 接受的不承諾撤回。
- 指定測試人員沿用現有測試機制；safe preview 不真的發 LINE，也不增加正式成效。

## 2. 共用資料契約與追蹤

各來源以 adapter 接入共用讀取介面；既有紀錄保留唯一來源，避免重複鏡像再加總。
新增功能與缺少的事件以 migration 建立補充資料表，禁止 runtime DDL。

邏輯契約：

| 欄位 | 意義 |
| --- | --- |
| source_type / source_id | welcome、broadcast、automation、keyword 與設定／批次 ID |
| execution_id / source_event_id | 單次執行與原始觸發；唯一鍵防止重送重計 |
| message_snapshot / revision | 當次實際內容，保留素材 ID／名稱，不以圖片網址識別 |
| variant / slot_index / action_index | A/B/C、段落及網址動作索引 |
| accepted / rejected / uncertain / skipped | LINE API 結果與原因，另記錄等待／執行中狀態 |
| occurred_at / test_only | 原事件時間及測試隔離標記 |
| recipient identity | 僅伺服器受權限保護保存；不可暴露於追蹤網址、文件或 fixture |

- 既有 `/r/b`、`/rf`、`/t/m`、關鍵字 A/B 跳板維持相容，不重複包裝 URL。
- 新追蹤目標保存完整原網址（含 UTM）、素材版本及動作索引。圖片相同但動作網址不同必須分開。
- 純文字中的 HTTP(S) 網址新增有界限的共用轉換器：保留文字、標點及查詢參數，不改非網址內容；無法可靠解析的網址保持原樣並提示不追蹤。預覽不計入成效。
- Imagemap 的 URI 區域及 Flex/Carousel 網址 action 分開統計；message/postback 不冒充網址點擊。本波不將圖片讀取或影片播放當成已讀。
- 未驗證身分的跳轉與已驗證點擊分開；預覽／已知爬蟲不計為有效點擊。只有可靠識別才能計不重複人數，不承諾排除所有機器流量。
- 舊資料缺來源／版本時標示未知或未追蹤，不按今天素材回填。資料庫讀取失敗顯示錯誤，不能回傳全 0；寫入失敗不得假稱完成。

## 3. 發送紀錄與訊息成效

- `/admin/push-logs` 保留原入口、過濾、CSV 保護與角色邊界，補四種來源與 reply 的執行結果；原推播診斷資訊不移除。
- 新增 `/admin/message-performance`，導覽放「看成效 → 訊息成效」。各設定頁加查看成效與查看紀錄深連結。
- 依台灣日期、來源、設定／批次、訊息版本及 A/B 篩選；日期用半開區間處理跨午夜。
- 顯示觸發次數、API 接受次數、失敗／不確定／略過、網址點擊次數；可靠資料源才顯示不重複人數。
- 展開可看各段／卡片／按鈕／圖文區域。每份報表顯示實際追蹤涵蓋範圍與資料起始時間。
- 不重複點擊率只在分子分母有一致身分及觀察範圍時顯示；其他來源顯示次數或明確標示「每百次接受發送的點擊次數」，不可共用一個誤導的 CTR。
- 群發、關鍵字 A/B 的原本觀察期及去重口徑保留，跨來源不直接合併為一個勝負結論。
- API 接受不等於 delivered/read；不支援為「不適用」，資料缺少為「尚未追蹤」，合法零值才為 0。訂位完成無串接就不顯示已轉換。

## 4. Campaign Testing：等待人工確認

- 建立頁新增 Winner 發送方式：人工確認（新建預設）／自動。既有已建立批次保留原設定，不偷偷改排程。
- 沿用 `audience_config.experiment.winnerMode` 與既有釋出 API；後端拒絕未知 mode，前端草稿與重載完整保留。
- 觀察期從最後一位測試收件人處理完成起算，延續既有邏輯。manual 到期只顯示待確認；排程不能釋出。
- 到期後顯示 A/B/C 實際接受數、可用點擊指標、選版與保留人數；選擇版本後確認才建立保留名單批次。未到期不可經 API 繞過。
- row lock、已釋出 ID 與狀態檢查共用；重按、兩人同時操作、cron 競態最多建立一批。記錄操作者、選版、時間及當時報表摘要。
- 沒有明確高低仍可人工選版，但標示「人工選擇」，不宣稱統計勝出。
- 本波不宣稱自動統計顯著。自動模式至少在任一版沒有成功樣本、全部零點擊或平手時暫停，轉待確認；不再直接以 A 優先當勝出。
- 建立頁呈現實際分組人數與小樣本提示；不將「每版 1,000 人」當成保證。保留一般 A/B 50/50 與 Campaign 的差異。

## 5. 動態名單隔日補送：排除指定測試批次

- 群發受眾新增「排除曾納入指定批次的測試名單」，可多選批次，明確顯示排除對象與人數。
- 排除以資料庫批次快照為準，含 A/B/C 的 pending、sending、sent、failed、uncertain、skipped 等全部測試對象；不能只排除成功者。Campaign holdout 不屬於已測試名單，不誤排除。
- 同一個共用受眾計算供預覽、隨機抽樣前、建立批次使用：先同步動態條件 → 去重及可發送資格 → 排除 → 隨機／限額 → 保存快照。排除查詢失敗禁止繼續。
- 新批次建立後固定收件人，不因 runner 執行或隔日名單增長再次補人。排程批次亦維持快照。
- 顯示動態名單的預覽時間；名單改變時需重新預覽確認，不沿用舊人數假稱一致。
- 操作「動態 pool 隔日補送」建立獨立批次，選用原 A/B 快照；保留對來源測試的引用，成效不加回原本 A/B 結果。
- 不擴張既有 Campaign holdout。要固定原始 1,283 人，需用原始快照；要包含新增符合者，才用隔日動態 pool 減原測試名單。
- 驗收例：今天 pool 1,283 人、測試 770；明天 pool 1,400 且原 770 仍在內 → 可補送 630。若有人退出條件，以實際集合差集計算，不能只用總數相減。

## 資料、安全與回滾

- 補充 schema 必須附 migration、rollback SQL、索引／唯一鍵、RLS 與 staging 專用角色權限測試；只在 crm_staging／隔離本機驗證。不自動觸碰 public。
- 歡迎事件申領與訊息版本不可只存在瀏覽器；後端保存、驗證並去重。保留 webhook raw-body 驗簽，所有關鍵寫入及發送 await。
- 追蹤代碼用不透明隨機識別，不包含 LINE ID／Email／電話；目的地從快照解析，檢查 URL scheme，避免任意開放轉址。
- 不會修改使用者既有素材／流程或啟用新排程。停用新歡迎設定與新批次自動選版是第一層運營回滾；程式回滾使用本波功能 commits 的 revert。
- schema rollback 在停用寫入並備份新增歷史後才執行；已寄出的訊息無法撤回，仍在使用的追蹤連結須保留相容讀取，不能直接刪表讓舊連結失效。

## 驗收與交付清單

- 所有現有樣式：選取、保存重載、預覽、builder、sender HTTP payload；Imagemap 同圖不同 URL 與多段順序。
- follow 首次／解除封鎖／未知、停用、重送、並行、逾時與既有 follow 流程相容；不干擾邀請／獎勵。
- 四種來源與相同素材不同來源／版本的歸因；URI／UTM、去重、非 URI 不追蹤、歷史缺值及測試隔離。
- manual runner 永不釋出、到期檢查、重按與並行一批、auto 無資料／平手停下；草稿與來源快照。
- 動態 pool 新增／退出／重複／已封鎖／部分失敗者排除、無效批次 ID、預覽與建立一致、資料庫失敗不放行。
- migration／rollback 在隔離 DB 回歸，RLS 無 public 跨 schema 權限。
- `npm ci --include=dev`、`npm test`、`git diff --check origin/main...HEAD`；固定 Staging 桌機／390px、console、水平溢出、畫面證據。
- 使用者 push 後才可驗證固定 Staging 的新功能；push 前的本機測試不得標成固定站已驗證。
- 更新 `docs/AI_HANDOFF.md`，交付 PR title、Hen review description、測試摘要、migration／rollback、實機未完成項目；Hen 核准保持未勾選。
